## bangumi_bg_custom.user.js

### v1.8.0（2026-09-19，用户要求修复）
- **深色模式与站点原生机制互通**：爬虫确认 bgm.tv 官方深色主题挂在 `html[data-theme="dark"]`（635 条规则，含正文/输入框/链接反色与 300ms 切换过渡）。偏好新增 `自动` 档（默认）：跟随站点右下角「关灯/开灯」开关与系统偏好；`亮色/暗色` 强制档在用户点击站点原生开关时自动采纳，不再把站点状态强改回 light（修复旧版互相拉扯的 bug）。配置面板改为 自动/亮色/暗色 三态。
- **玻璃全区域统一**：删除与 token 规则取值不一致的陈旧硬编码（通用头部 .5/.6/.7、`.columns.clearit` .3、`.mainWrapper` 双重定义、`#main.png_bg` 的 --35）；`div#main` 亮色模式补上与深色一致的 backdrop-filter，同页磨砂层数统一；`--bgc-glass/--bgc-blur/--bgc-saturate` 注释明确为跨脚本共享契约。
- **可读性**：`color-scheme` 亮/暗切换；正文微光晕（浅色白光晕/深色黑光晕）；`small.grey`、`q` 等次级文字对比度提高；强调色接入站点 `--primary-color` 主题色变量；深色统一模糊列表加入 no_api 时间轴宿主。

## bangumi_calendar_timeline.user.js

### v1.2.0（2026-09-19，用户要求修复）
- **修复玻璃 token 冲突**：删除自建 `--bgc-glass: 38,38,46`（与 bg_custom 的 16,18,28 冲突，同页互相覆盖导致深浅不一），改为与 bg_custom 完全同值的 token 定义；深色区 `#26262e/#333` 等硬编码全部变量化。
- **补齐缺失的背景玻璃层**：旧版 API 变体不读取 bg_custom 背景/透明度配置（只有 no_api 有），装背景后卡片仍是死白；新增与 no_api 相同的 bgStyle 适配块（模糊统一走共享 token，深浅双变体）。
- **深色检测升级**：优先级改为 共享偏好 > 站点原生 `data-theme` > 旧式 class > body 亮度 > `prefers-color-scheme`，观察器增加 `data-theme` 属性；bg_custom 缺席时代写站点主题属性（官方深色 CSS 才会生效）。
- **深色生效时机提前**：旧版在集数全部拉取完才应用深色（可能迟到数十秒），现脚本加载即应用。
- 可读性：脚注/空态/次级文字对比度提高；模糊 4px/3px 与全站 12px 统一；强调色接入 `--primary-color`。

## 共享约定（v1.8.0/v1.2.0/v1.3.0 起）

1. 玻璃唯一事实源：`--bgc-glass`（浅 `255,255,255` / 深 `16,18,28`）、`--bgc-blur: 12px`、`--bgc-saturate`（浅 `160%` / 深 `150%`）；各脚本同值定义，注入顺序不影响结果。**修改深色玻璃底色时四个文件必须同步改。**
2. 深色判定语义（四个文件一致）：共享偏好 `'on'/'off'`（localStorage `bangumi-bg-custom-dark-mode`）> 站点原生 `html[data-theme]` > 旧式深色 class > body 亮度 > `prefers-color-scheme`。
3. 强制档只定初始值：用户点站点原生开关后，偏好自动采纳为新值，任何脚本不再抢回。
4. 强调色统一走 `var(--primary-color, #f091xx)`，跟随用户在站点选择的主题色。
